## Summary of Key Differences

Rows are grouped by likely effect on final model performance. Items marked *no expected impact* are listed for completeness but should not explain any performance gap.

### Material — most likely explanations for a performance difference

1. **`Weatherconditions` missing-value handling (DIFFERENT).** My case-sensitive `.replace('nan', np.nan)` never converts the marker, so 569 rows keep a literal `'NaN'` string as a 7th category and the mode fill is a no-op. Friend converts correctly and mode-fills with "Fog", ending with 6 balanced categories. I am feeding a spurious category and mis-assigning 569 rows.
2. **`City` missing-value handling (DIFFERENT).** I mode-fill 1,114 rows into `Metropolitian` (3 levels, distribution shifted); friend assigns an explicit `"Unknown"` bucket (4 levels, missingness preserved as signal).
3. **`Time_Orderd` missing-value handling (DIFFERENT).** I leave 1,600 `NaT` values and let the gap propagate into `Prep_Time_min`; friend back-fills the timestamp as `Time_Order_picked − median(10 min)`, so the downstream feature is fully populated at source.
4. **`Prep_Time_min` missing handling, rollover correction, and retention (DIFFERENT).** I mean-impute 1,600 gaps, add 1440 to negative durations, and keep the column; friend documents no missing handling, no rollover correction, and explicitly drops the column at `finalize_columns()`. (Friend claims an identical 5/10/15 tri-modal distribution, which if true makes the numeric impact small — but the documented method is not the same.)
5. **`Delivery_person_Age` imputation and placeholder handling (DIFFERENT).** Mean 29.5178 → 29 vs median 30.0 for ~1,700–1,850 rows; placeholders 15/50 nulled and re-imputed vs `.clip()`-ed to 20 and 40. Final range 20–39 vs 20–40.
6. **`Vehicle_condition` treatment (DIFFERENT).** I leave it completely untouched; friend casts to `category` and treats it as an ordinal 0–3 scale. Different dtype and different implied encoding at model input.
7. **Engineered features absent from friend's documentation (MISSING).** `Distance_km` (Haversine, R = 6371.0 km) and `Is_Weekend` (dayofweek in [5,6]) exist only in my pipeline. Route length and day-type are plausible strong predictors, so their absence is a leading candidate explanation for a performance gap — subject to the caveat that friend may compute them in the undocumented feature-engineering script.
8. **Final column set (DIFFERENT / MISSING).** I document the 20 → 15 reduction and exactly which 8 columns are dropped; friend documents only the two identifier drops plus the two computed columns discarded by `finalize_columns()`, with no final column list or count. The two pipelines may not be comparable feature-for-feature.
9. **Row-removal criterion (DIFFERENT).** Same 3,640 rows removed and the same 41,953-row result, but my rule is a four-column `abs < 1` threshold while friend's is an exact restaurant `(0,0)` test. Because the outcome is numerically identical, this is unlikely to matter — flagged because the logic is genuinely different and would diverge on other data.
10. **Pipeline stage structure (DIFFERENT).** Friend has an intermediate `food_delivery_cleaned.csv` stage with a `finalize_columns()` gate that silently discards computed columns; mine goes directly from cleaning to the 15-column feature frame. Relevant to reproducibility rather than to the model itself.
11. **`Temp_taken` / outlier and downstream steps not documented by either file (MISSING).** **Train/test split, encoding strategy, and model choice are absent from both files**, so they cannot be compared. Any performance difference could equally originate there. The two files only cover cleaning and feature engineering.

### No expected impact

12. **`multiple_deliveries` imputation label (DIFFERENT, immaterial).** Mode (mine) vs median (friend) — both resolve to 1, so the imputed values are identical. Both keep the 327 value-3 rows.
13. **`Type_of_order` whitespace (DIFFERENT, immaterial).** Friend strips label whitespace; I leave it untouched. Same 4 semantic categories.
14. **`Delivery_person_Ratings` count discrepancy (OK on approach).** Approach matches (median 4.7 imputation, `> 5` nulled then re-imputed, never clipped), but the reported number of impossible `> 5` rows differs: 46 in my file vs 53 in friend's. Not reconcilable from either file; my file itself notes the notebook markdown claimed "a single row" against 46 verified in the stored output.
15. **`Order_Date` retention (MISSING in friend).** Both parse identically; only I document keeping the column and using it for `Is_Weekend`. Largely subsumed by item 7.
16. **`temp_city_code` conditional drop (MISSING in friend).** A no-op in my pipeline; documented nowhere in friend's file.
