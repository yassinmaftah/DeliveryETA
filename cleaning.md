# Data Cleaning and Feature Engineering Summary

## Summary

- **Original dataset:** 45,593 rows x 20 columns (`data/raw/dataset.csv`, loaded in notebook exec 199).
- **After Step 1 (data cleaning):** 41,953 rows x 20 columns. No columns were dropped in Step 1; the cleaned frame has 0 missing values in every column (notebook exec 229).
- **After Step 2 (feature engineering):** 41,953 rows x 15 columns. 8 source columns were dropped (4 GPS coordinates, `ID`, `Delivery_person_ID`, `Time_Orderd`, `Time_Order_picked`) and 3 new columns were created (`Distance_km`, `Is_Weekend`, `Prep_Time_min`).
- **Total rows removed: 3,640** (7.98% of 45,593). This is the only row deletion anywhere in the pipeline. Reason: rows where any of the four GPS coordinates had an absolute value below 1 (observed minimum 0.01) - physically implausible locations (in the ocean / far from India) that the notebook markdown describes as unrecoverable (exec 221, 230).
- **Rows deliberately not removed:** 0 exact duplicate rows existed (`df.duplicated().sum() == 0`, exec 224); 247 `Time_taken(min)` IQR outliers above 51.50 min were kept because they were attributed to `Road_traffic_density = Jam` and adverse conditions, i.e. legitimate delays (exec 241, 243, markdown "Outlier Analysis"); invalid age and rating values were imputed, never dropped.
- **Notes:** the conditional `temp_city_code` drop never triggered because that column is not present in the dataset. `Vehicle_condition` and `Type_of_order` were not touched by Step 1 or Step 2. The `'NaN '` markers on `Delivery_person_Age`, `Delivery_person_Ratings` and `multiple_deliveries` were counted on the original 45,593 rows (before the GPS row filter), whereas `City`, `Road_traffic_density`, `Festival` and the age/rating placeholders were counted on the 41,953 rows remaining after the filter, matching the order in which the notebook executed those cells.
